## Host optimization measurement

GCC16.2.1 -O2, Ryzen5 4600G, stereo 48kHz/512 frames. Eight cases each simulate
60s offline; density12/80, size80/250ms, mono/stereo with 131,072 source frames.
Making the normalized sample accessor inline exposes unchanged bounds checks
and reads to the optimizer, avoiding four out-of-line calls per active stereo
voice/sample. No DSP equation changed. Sampled checksums match all eight cases;
numeric and chunk-boundary regressions pass. This is not a full waveform hash
comparison across all compilers or device sound validation.

## Host-only timing evidence

Host: AMD Ryzen5 4600G, x86_64, Linux7.3.3-1-cachyos. GCC16.2.1.
`c++ -std=c++17 -O2 -Wall -Wextra -Wpedantic -Iinclude src/dsp/tone.cpp benchmarks/tone_benchmark.cpp -o build/tone-benchmark-release`
then `build/tone-benchmark-release`: 60 seconds of offline synthetic stereo tone,
48kHz, 512 frames, 5,625 blocks. Observed p95 **8.205us**, p99 **11.492us**, max
**57.288us**, against arithmetic 10,666.667us deadline. Microbenchmark covers
only the tone renderer, not SDL/OS/real-time scheduling or a granular engine.
These numbers do not predict MM+ CPU headroom.

Five seconds of host SDL dummy silence: 242 callbacks, late hints=0, max callback
310us in one run (77us in another). XRUNs unavailable. Python resource.getrusage
reported 13,220 KiB peak child RSS across the repeated host runs; this is an
aggregate high-water mark, not isolated device app RSS. No on-device latency,
RSS, underrun, listening-quality, power or long-soak result exists.
